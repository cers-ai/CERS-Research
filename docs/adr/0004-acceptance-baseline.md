# ADR-0004：发布判定以 GP-01–GP-18 为唯一验收基线

- 状态：Accepted
- 日期：2026-10-28
- 决策者：产品负责人 / 技术负责人
- 关联：功能开发需求 §8、§11.2；产品需求规格说明书 §18

## 背景

PRD §18 与功能开发需求 §8 各有一套验收清单，编号与覆盖范围并不一一对应。若并列使用，容易出现"PRD 勾完就宣布发布"或"GP 通过但需求项漏检"的争议。

## 决策

1. **功能开发需求 §8 的 GP-01–GP-18 是发布判定的唯一基线**。
2. PRD §18 保留为需求侧自查清单，用于确认产品行为覆盖，不作为发布门槛。
3. 每个 GP 必须能映射到至少一个 FR-ID；新增 GP 需同时更新矩阵与责任人。
4. 页面完成、前端 mock、截图、预置数据均不能替代 GP 的真实运行证据。

## 理由

- GP 矩阵同时包含正向、负向、中断恢复与安全场景，比功能勾选更接近真实发布风险。
- 单一基线避免团队在"哪个清单更重要"上反复讨论。

## 后果

- 发布评审只看 GP 结果 + 已知缺口清单。
- PRD §18 若与 GP 冲突，先修 PRD 描述，不得降低 GP 标准。
- 任何 P0 功能缺失必须列为明确缺口，不能以"后续迭代"模糊带过。
