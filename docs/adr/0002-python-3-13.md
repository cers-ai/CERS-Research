# ADR-0002：Python Sidecar 锁定 CPython 3.13.x

- 状态：Accepted
- 日期：2026-10-28
- 决策者：技术负责人 / 项目负责人
- 关联：技术方案 §2.2、§17.2；功能开发需求 §1.4

## 背景

技术方案原写"Python 3.12/3.13，以依赖兼容性测试锁版本"。开发机实际系统 Python 为 3.14.4，若不明确锁定，Sidecar 会随开发机/用户机器版本漂移，导致 wheel、PyInstaller、类型行为和打包结果不一致。

## 决策

1. **交付与开发统一使用 CPython 3.13.x**，不在此版本之外做兼容承诺。
2. 用 `uv` 安装解释器并锁定依赖：仓库根 `.python-version` = `3.13`；`services/research-worker` 与 `packages/contracts/python` 的 `requires-python` 为 `>=3.13,<3.14`。
3. Sidecar 打包时**内置运行时**，启动时校验 `sys.version_info[:2] == (3, 13)`；不读取系统 Python，不要求用户安装 Python。
4. CI 只使用 3.13.x 跑 Python 测试；升级到 3.14 必须另开 ADR，并附打包、wheel、科学计算依赖与导入耗时验证。

## 理由

- 3.13 已有稳定的科学计算与打包生态，风险低于 3.14。
- 明确单一版本可避免"本机 3.14 能跑、安装包 3.13 失败"的隐性缺陷。
- 与 uv 的 lockfile 配合，可复现构建。

## 后果

- 开发者首次拉取仓库需要执行 `uv python install 3.13` 与 `uv sync`。
- 不允许在 `pyproject.toml` 中使用 `>=3.12` 之类的宽范围声明。
- 依赖若只支持 3.14，不得引入；必须寻找替代或延后。

## 验证

- `uv run python -c "import sys; assert sys.version_info[:2] == (3, 13)"`
- Sidecar 启动自检失败时给出明确错误并退出，不静默降级。
- Windows 安装包内 `python313.dll` / 运行时目录存在且版本正确。
