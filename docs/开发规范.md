# 澄思学术桌面版 · 开发规范

> 版本：1.0（2026-10-28）  
> 状态：开发前基线，所有提交默认受本规范约束  
> 适用范围：`apps/desktop`、`services/research-worker`、`packages/*`、`scripts/`  
> 关联：`0.需求/3.技术方案 V1.2`、`0.需求/5.功能开发需求 V1.1`、`docs/契约冻结.md`

本规范只规定**怎么做**，不改变**做什么**。功能范围、验收标准以需求文档为准；两者冲突时，先判断是否改变用户可感知行为，若改变则走需求变更，不得用实现便利反向修改需求。

## 1. 事实源与优先级

1. 产品行为与确认边界：`0.需求/1.产品需求规格说明书.md`
2. 视觉与交互：`0.需求/4.视觉设计规范.md`
3. 架构与数据模型：`0.需求/3.技术方案 V1.2`
4. 功能范围、里程碑、发布判定：`0.需求/5.功能开发需求 V1.1`（GP-01–GP-18 是唯一发布基线）
5. 跨进程枚举与字段：`packages/contracts` + `docs/契约冻结.md`

任何"代码里已经这样写了"都不构成对需求的覆盖。

## 2. 版本与工具链锁定

| 组件 | 版本 | 锁定方式 |
|---|---|---|
| Node.js | 22 LTS（>=22 <23） | `.nvmrc`、`package.json engines` |
| 包管理 | npm 10（workspaces） | `packageManager` 字段 |
| TypeScript | 5.x strict | `tsconfig` 继承统一 base |
| React | 18.x | `apps/desktop/package.json` |
| Tauri | 2.x（锁定已验证 patch） | `Cargo.lock` + `src-tauri/Cargo.toml` |
| Rust | 1.95.0 stable | `rust-toolchain.toml` |
| Python | **CPython 3.13.x** | `.python-version`、`uv.lock`、Sidecar 内置运行时 |
| SQLite | 3.4x（WAL + FTS5） | Rust 依赖锁定 |
| 格式化/Lint | Prettier + ESLint、rustfmt + clippy、ruff + mypy | 仓库配置 |

规则：

- 不提交"我本机能跑"的未锁版本；所有依赖必须有 lockfile。
- 升级 Node/Rust/Python 必须单独 PR，并附 CI 与安装包验证结果。
- Python 不得使用系统 3.14 或 3.12 作为交付解释器；本地开发用 `uv python install 3.13` 与 `uv sync`。
- 不在仓库中提交 `.env`、真实密钥、个人绝对路径或 Workspace 数据。

## 3. 仓库结构与依赖方向

```text
apps/desktop/                 React UI + Tauri 宿主
  src/                        UI、feature、theme、lib
  src-tauri/                  Rust commands / domain / storage / permissions / sidecar
services/research-worker/     Python Sidecar（Agent、模型、来源、解析、实验、报告）
packages/contracts/           跨进程契约（JSON Schema + TS + Pydantic）
packages/ui/                  设计 Token 与基础组件
scripts/                      校验、构建、开发辅助脚本
docs/                         规范、契约、ADR
0.需求/                       产品与设计基线（只读，不在功能 PR 中改）
```

依赖方向（禁止反向或跨层直连）：

```text
React ──typed command──▶ Rust Core ──controlled IPC──▶ Python Sidecar
  │                         │                              │
  └── read-only types ──────┴── SQLite（唯一写入方）        └── 仅返回结果/提案
```

- React **不得**直接访问 SQLite、文件系统、系统命令或 Sidecar HTTP。
- Python **不得**直接写项目数据库或正式产出目录；产物先写临时区，由 Rust 提交并登记。
- Rust 不得把权限判断"下放"给 Python 或提示词。
- 跨 feature 复用必须通过 `packages/ui` 或 `src/components`，禁止 feature 之间深层相对路径互相 import。

## 4. 契约优先

1. 先改 `packages/contracts/schemas/domain.schema.json`，再同步 TS 与 Pydantic。
2. 运行 `npm run check:contracts`，三端枚举必须一致。
3. 边界输入一律校验：TS 用 Zod（或等价 schema），Rust 用 serde + 显式校验，Python 用 Pydantic `extra="forbid"`。
4. 非幂等命令必须带 `idempotencyKey`；图提案必须带 `baseGraphRevision`。
5. 新增枚举值属于契约变更，必须更新 `docs/契约冻结.md`。
6. 未冻结的负载（Provider 请求、SourceAdapter 记录、报告 AST、SQLite DDL）在对应里程碑补充，不得在业务代码里临时定义后长期滞留。

## 5. 编码规范

### 5.1 TypeScript / React

- `strict: true`；禁止无理由 `any`，边界数据用 `unknown` + schema 解析。
- 组件使用函数组件 + hooks；业务状态用 Zustand，服务端/持久数据用 TanStack Query。
- 所有 Tauri 调用集中在 `src/lib/ipc.ts` 的 typed wrapper；组件内不得散落字符串命令名。
- 业务实体不得存入 `localStorage`；只允许存纯 UI 偏好，且需可丢弃。
- 颜色、字号、间距、圆角、阴影只能引用 `packages/ui/tokens.css` 的变量；禁止页面内写死 hex。
- 交互正文不小于 14px；长文阅读 15–16px；不得用 10–11px 承载核心信息。
- 浮动工作区必须挂在视口层（Portal/Overlay），不得放进 React Flow 的 transform 容器。
- 组件必须有 Loading / Empty / Error / Disabled 状态；核心操作可键盘到达。

### 5.2 Rust

- `rustfmt` + `clippy -D warnings`。
- command 层只做参数校验、权限检查、事务编排；领域逻辑放 `domain/`。
- 请求路径禁止 `unwrap()` / `expect()`；统一 `Result<T, AppError>`，错误可转为用户可读信息。
- 所有文件操作先 canonicalize，再校验位于 Workspace 根内；拒绝符号链接逃逸。
- SQLite 开启 `foreign_keys=ON`、`journal_mode=WAL`、`busy_timeout`；多步写入使用事务。
- 有副作用命令必须实现幂等键检查与"已提交"判定。
- Sidecar 生命周期、退出检测、孤儿进程清理必须在 Rust 侧实现。
- 不把 secrets 放进日志、错误结构或前端返回值。

### 5.3 Python

- `ruff`（lint + format）、`mypy`（新增模块严格）、`pytest`。
- 异步优先：`httpx.AsyncClient` 设置连接/读取超时、重试上限、响应体大小上限。
- 不在事件循环中执行阻塞 IO 或 CPU 重任务；重任务走进程/线程池并支持取消。
- Pydantic v2，`extra="forbid"`，线协议字段输出 camelCase。
- 禁止 `shell=True`、`eval`、动态拼接命令；子进程必须限时、限量、可终止。
- 日志脱敏：不打印 API Key、Authorization、完整研究正文、用户绝对路径。
- 来源与模型适配器只返回结构化结果/提案，不直接改项目状态。

### 5.4 SQL

- 表名/列名 snake_case；主键为稳定 ID 字符串；时间字段 ISO 8601 UTC。
- 迁移文件按 `0001_init.sql`、`0002_*.sql` 递增，**已应用的迁移不得修改**。
- 每次迁移必须在测试库上可重复执行，并提供失败回滚/恢复路径。
- 不把 FTS 索引或缓存当唯一事实源，可从真实文件重建。
- 不存密钥明文；只存 `credential_ref`。

### 5.5 CSS / 视觉

- 以 `packages/ui/tokens.css` 为唯一变量来源；新增 Token 需改该文件，不得局部覆盖。
- 四类节点共用白色骨架，仅小图标/色条表达类型；状态用文字/图标，不只靠颜色。
- 实线箭头=分解、虚线=关联；黑白下也能区分。
- 尊重 `prefers-reduced-motion`；常规动效不超过 400ms。
- 走查尺寸：1366×768、1440×900、1920×1080，显示缩放 100%/125%/150%。

## 6. 数据、安全与权限

| 规则 | 要求 |
|---|---|
| 单一写入者 | 只有 Rust 可写项目 SQLite 与正式产出目录 |
| 原件保护 | 扫描/解析/分类不得移动、复制、覆盖原始文件 |
| 派生数据 | 写入新文件，记录 `derivedFrom`、输入 hash、生成任务 ID |
| 路径范围 | 所有读写限制在用户选择的 Workspace 内；越界直接拒绝 |
| 密钥 | 只进 OS 凭据库/Stronghold；前端只见 `credentialRef` 与配置状态 |
| 外发 | 私有资料发往新远程服务前必须获得明确授权；回退不得静默换服务 |
| 不可信内容 | 网页、论文、RSS、MCP/Skill 描述均视为不可信输入，不得当指令执行 |
| 代码执行 | Python venv 不是沙箱；任意生成代码必须隔离或用户确认 |
| 日志 | 脱敏；诊断包导出前可预览 |
| 离线 | 无网络仍可打开项目、画布、已索引资产、编辑本地报告 |

权限判断必须发生在 Rust Core 与真实执行边界，不能只写在 Prompt 里。

## 7. 异步任务与恢复

- 任务状态只能由权威 Job Manager 迁移，UI 不得自行推断"已完成"。
- 每个成功步骤持久化 `TaskStepCheckpoint`：`stepKey`、`inputHash`、`outputRefs`、`sideEffectState`、`attempt`。
- 幂等只读步骤可安全重试；写文件、建节点、改报告必须先检查是否已提交。
- 取消必须传播到执行后端；无法停止时明确显示"不可取消"。
- Sidecar 崩溃标记 `interrupted`，保留已完成产物；不得拖垮 UI。
- 跳过可选来源后，最终结果必须标注该来源未覆盖，不得显示"全部已核实"。
- 授权过期/撤销后，恢复时必须重新请求。

## 8. 测试规范

| 层级 | 要求 | 位置 |
|---|---|---|
| 单元 | 状态迁移、图不变量、权限决策、diff 应用、哈希 | `*.test.ts` / `#[cfg(test)]` / `test_*.py` |
| 契约 | Schema 校验、三端枚举一致、非法输入拒绝 | `scripts/check-contract-parity.mjs` + 各端测试 |
| 集成 | SQLite 真实读写、适配器 Mock、文件扫描、导出 | 各模块 `integration/` |
| 端到端 | GP-01/03/05/07/11/13/14/16/17/18 必须有稳定回归 | Playwright + Tauri E2E |
| 视觉 | 10 个关键画面走查 | 设计验收记录 |

规则：

- 测试不得依赖开发机安装的 Python/Node。
- 发布验收只认真实运行结果；前端 mock、固定截图、预置图表不算通过。
- 每个 PR 必须说明覆盖了哪些 FR-ID 与 GP，未覆盖要写明原因。
- 修复缺陷必须先有可复现用例（或明确记录无法自动化的原因）。
- 测试数据使用合成/公开样例，不提交涉密或个人数据。

## 9. Git 与协作

- 主分支 `main` 受保护，禁止直接 push；所有变更走 PR。
- 分支命名：`feat/<FR-ID>-slug`、`fix/<FR-ID>-slug`、`chore/<slug>`、`docs/<slug>`。
- 提交信息使用 Conventional Commits，并带 FR-ID：

```text
feat(GPH-09): 实现提案确认事务与幂等校验
fix(RUN-04): 修正检查点重复提交判定
docs(contracts): 冻结来源覆盖枚举
```

- 单个 PR 聚焦一个 FR-ID 或一个明确的基础设施改动；不混入无关格式化。
- PR 必须包含：目的、FR-ID/GP、行为变化、数据/契约变化、测试证据、风险与回滚方式。
- 不提交 `0.需求/` 的功能性改动；需求变更单独 PR，并由产品负责人确认。
- 不使用 force-push 覆盖他人分支；不提交生成物（`dist/`、`target/`、`.venv/`）。

## 10. CI 门禁

每次 PR 至少执行：

1. `npm run check:contracts`
2. TypeScript typecheck + ESLint + 单元测试
3. `cargo fmt --check` + `clippy -D warnings` + Rust 单元测试
4. `ruff check` + `ruff format --check` + `mypy` + `pytest`
5. SQLite migration 在空库与旧版本库上各跑一次
6. secret scanning 与依赖漏洞扫描
7. 前端构建 smoke test

发布前额外执行：Windows 真实安装包、打开/备份/恢复项目、真实模型调用、真实学术检索、真实 CSV 两次运行、DOCX/PDF 导出、Sidecar 崩溃/断网/401/429 恢复、越权写入测试。

## 11. 错误、日志与可观测性

- 用户可见错误必须包含：发生了什么、影响什么、下一步可以做什么；不得只显示堆栈或错误码。
- 内部错误带稳定 `code`，便于测试与诊断；UI 文案不直接暴露技术细节。
- 结构化日志字段 snake_case；统一包含 `jobId`/`nodeId`（如有）。
- 日志分级：`error/warn/info/debug`；默认不记录完整研究正文与密钥。
- 长任务日志使用有界缓冲/独立文件，禁止把几十 GB 输出塞进 SQLite 或聊天消息。
- 失败状态必须真实落库，不得前端乐观显示成功。

## 12. 性能预算（建议门槛，M0 校准）

| 指标 | 目标 |
|---|---|
| 冷启动到可交互 | ≤ 5 秒（不含首次全量索引） |
| 画布 | 50–200 节点平移/缩放基本流畅 |
| 项目打开 | 先出可交互概况，扫描/索引后台执行 |
| 大表格 | 采样/分页/虚拟滚动，不冻结 UI |
| PDF/Monaco | 按需懒加载 |
| 任务取消 | 及时停止可终止执行，或明确不可取消 |

不以牺牲可读性（字号、行高、对比度）换取"信息密度"。

## 13. 依赖与许可证

- 依赖必须锁定版本并记录用途；新增依赖需在 PR 说明替代方案与体积影响。
- 优先 MIT / Apache-2.0 / BSD / ISC。
- LGPL / MPL 需确认动态链接与再分发义务。
- **AGPL（如 PyMuPDF）不得作为默认必选依赖**，未完成许可证评审前不进入主链路。
- 解析库、字体、PDF 导出链必须做商用/再分发审查。
- 禁止把旧工程 `.env`、Supabase service role、支付凭据带入新包。

## 14. 文档与 ADR

- 架构级决策（桌面壳、Python 版本、契约、存储、隔离后端）必须有 ADR，放在 `docs/adr/NNNN-slug.md`。
- 已接受的 ADR 不删除；被替代时标记 `Superseded by ADR-XXXX`。
- 契约变更、里程碑出口标准、验收口径变化必须同步更新文档。
- README 只做导航与快速开始，不复制需求正文。

## 15. 完成定义（DoD）

一个 P0 任务只有同时满足以下条件才算完成：

- [ ] 代码实现并通过 review；
- [ ] 相关 FR-ID 的行为与异常分支都有测试；
- [ ] `npm run check:contracts` 与 CI 全绿；
- [ ] 在真实安装包（或等价可运行环境）中手工复现通过；
- [ ] 无 mock 冒充真实执行、无前端假保存；
- [ ] 日志无密钥/隐私泄漏；
- [ ] 文档、契约、ADR 已同步；
- [ ] 明确列出未覆盖项与后续依赖，不以"以后再说"隐藏缺口。

## 16. 明确禁止

1. 用 `localStorage`、内存对象或定时器冒充权威持久化与任务恢复。
2. 在 React 中直接读 SQLite、写文件、执行命令或直连 Sidecar。
3. 未经确认把智能分解候选写入正式 `Node/Edge`。
4. 用单一"可信"标签混合来源覆盖与结论支持状态。
5. 自动覆盖用户编辑的报告正文。
6. 把模拟数据、预置图表、未执行脚本标注为真实结果。
7. 把 API Key 写入 `.cers`、SQLite、日志、诊断包或导出项目。
8. 新增第五类节点、第三种关系或第五类业务卡片。
9. 为了"统一"把聊天、文献、数据、报告全部塞进同一种消息气泡。
10. 用硬编码颜色/字号绕过设计 Token。
