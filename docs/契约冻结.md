# 跨进程契约冻结 v1

> 状态：**已冻结**（2026-10-28）  
> 适用：React（TS）↔ Rust（Tauri Commands）↔ Python Sidecar  
> 唯一事实源：`packages/contracts/schemas/domain.schema.json`  
> 镜像实现：`packages/contracts/ts/domain.ts`、`packages/contracts/python/cers_contracts/domain.py`  
> 自动校验：`node scripts/check-contract-parity.mjs`

本文件解决的是**开发前必须唯一确定、否则三端必然对不上**的口径问题。它不新增业务功能，也不改变任何 P0 范围。

## 1. 命名、标识与版本

| 项目 | 冻结结论 |
|---|---|
| 线协议字段 | **camelCase**（Tauri command、Sidecar IPC、JobEvent、GraphProposal） |
| 磁盘格式字段 | **snake_case**（`.cers`、`project.sqlite`、日志内的结构化字段按各端习惯） |
| Python 模型 | 属性 snake_case，序列化别名 camelCase（Pydantic `alias_generator=to_camel`） |
| Rust 序列化 | `#[serde(rename_all = "camelCase")]`，数据库列保持 snake_case |
| 时间 | ISO 8601 UTC，带 `Z`，例如 `2026-10-28T08:00:00Z` |
| ID | `<前缀>_<26 位小写 Crockford ULID>`，例如 `node_01j9m2...`；前缀见下表 |
| 契约版本 | 整数 `schemaVersion` / `CONTRACT_VERSION`，当前为 `1` |
| 枚举大小写 | 全小写 snake_case；中文只作为 UI 展示标签 |

ID 前缀：`prj`（项目）、`node`、`edge`、`prop`（提案）、`act`（ResearchAction）、`job`、`evt`、`asset`、`src`（SourceRecord）、`ev`（Evidence）、`rep`（报告）、`run`（ExperimentRun）、`chg`（报告单项变更）。

## 2. 冻结枚举

### 2.1 结构与状态

| 枚举 | 取值 | UI 标签 |
|---|---|---|
| `NodeType` | `root / research / experiment / report` | 总课题 / 研究 / 实验 / 报告 |
| `EdgeKind` | `decomposition / association` | 分解（实线箭头） / 研究关联（虚线） |
| `NodeState` | `ready / running / waiting_approval / attention / result_available` | 待开始 / 执行中 / 待确认 / 需关注 / 有结果 |
| `ProposalStatus` | `draft / awaiting_approval / approved / rejected / applied` | 草稿 / 待确认 / 已批准 / 已拒绝 / 已应用 |
| `JobStatus` | `queued / running / waiting_approval / paused / retry_pending / completed / failed / interrupted / cancelled` | 待开始 / 执行中 / 等待确认 / 已暂停 / 待重试 / 已完成 / 失败 / 已中断 / 已取消 |
| `AssetStatus` | `indexed / parsing / unsupported / missing / relocated / error` | 已索引 / 解析中 / 不支持 / 缺失 / 已重定位 / 错误 |
| `AutonomyLevel` | `cautious / balanced / autonomous` | 谨慎 / 均衡（默认） / 自主 |

### 2.2 证据与内容来源

| 枚举 | 取值 | UI 标签 |
|---|---|---|
| `SourceCoverage` | `metadata_only / abstract_only / fulltext / unavailable` | 仅题录 / 仅摘要 / 已获全文 / 不可获取 |
| `ClaimStatus` | `unverified / inferred / insufficient_evidence / partially_supported / supported / disputed / refuted` | 待核验 / 推断 / 证据不足 / 部分支持 / 有支持证据 / 存在争议 / 已被反驳 |
| `ContentOrigin` | `retrieved_metadata / extracted_text / model_summary / hypothesis / experiment_result` | 接口元数据 / 抽取原文 / 模型总结 / 待验证假设 / 实验结果 |
| `DataSensitivity` | `public / internal / private` | 公开 / 内部 / 私有 |

**正交规则**：`SourceCoverage` 只回答"拿到了多少内容"，`ClaimStatus` 只回答"证据支持到什么程度"。取得全文不得自动把结论置为 `supported`；只有摘要时不得给出正文页码。

### 2.3 报告

| 枚举 | 取值 | 说明 |
|---|---|---|
| `ReportProvenance` | `user / ai_accepted / ai_edited / external` | 段落来源；用于冲突提示，不要求用户逐段标注 |
| `ReportChangeReview` | `pending / accepted / rejected / conflict` | **单项级**审阅状态 |
| `ReportChangeProposalStatus` | `pending / partially_applied / applied / rejected / conflict` | **提案级**状态；部分接受为 `partially_applied` |

## 3. 本轮冲突的裁决记录

| 编号 | 原冲突 | 裁决 | 理由 |
|---|---|---|---|
| C-01 | `SourceCoverage` 存在 `citation / abstract` 与 `metadata_only / abstract_only` 两套写法 | 统一为 `metadata_only / abstract_only / fulltext / unavailable` | 语义更准确；与 FRS §5.3 一致 |
| C-02 | `ClaimStatus` 技术方案 6 值、FRS 4 值 | 取并集 7 值（增加 `insufficient_evidence`，保留 `inferred / partially_supported / refuted`） | 不丢失"已查但不足""推断""被反驳"三种真实科研状态 |
| C-03 | 报告变更只有一套 `pending/accepted/rejected/conflict` | 提案级与单项级分开，两套状态都持久化 | 部分接受必须有唯一可判定的提案状态 |
| C-04 | `Asset.status` 无 `relocated` | 增加 `relocated` | PRD 要求"文件移动后保留引用并可重定位" |
| C-05 | `JobStatus` FRS 7 值、技术方案状态机含 `paused / retry_pending` | 取并集 9 值，FRS 的 7 值为最小必需子集 | 不改变可见状态，只补全内部状态机 |
| C-06 | 线协议同时出现 `event_id` 与 `projectId` | 线协议统一 camelCase；磁盘 `.cers` 保持 snake_case | 与 TS 前端、Tauri serde、Pydantic alias 一致 |
| C-07 | 验收存在 PRD §18 与 FRS GP-01–GP-18 两套 | GP 矩阵为发布判定唯一基线，PRD §18 为需求侧自查 | 避免"通过了一处勾选就宣布完成" |
| C-08 | 技术方案引用"V5.0"但文件无版本号 | 技术方案 §23.2 固定文档映射；本文件记录当前版本 | 防止团队找错基线 |
| C-09 | Python 版本写为"3.12/3.13，按兼容性锁定" | 锁定 **CPython 3.13.x**，uv 管理，Sidecar 内置运行时 | 用户指定；避免系统 Python 漂移 |

## 4. 必须随契约一起遵守的不变量

1. 每个项目恰好一个 `root` 节点；`NodeType` 只有四种。
2. `decomposition` 不得自环或成环；`association` 可跨分支。
3. 提案在用户确认前不得写入正式 `Node/Edge`；确认提交必须带 `idempotencyKey` 与 `baseGraphRevision`。
4. `SourceCoverage` 与 `ClaimStatus` 正交；无全文不得产生页码定位。
5. `ReportChangeProposal` 绑定 `baseRevision`；`conflict` 时不得写入。
6. `ExperimentRun` 新运行不覆盖旧运行；原件只读，派生文件记录来源与哈希。
7. 密钥、JWT、授权头不得进入契约对象、日志或 Workspace 文件。
8. 所有非幂等写操作必须可判定"是否已提交"，恢复时不得自动重放。

## 5. 变更流程

1. **先改 JSON Schema**，再改 TS 与 Pydantic，同一 PR 内完成。
2. 新增**可选**字段属于向后兼容变更，`schemaVersion` 保持 1。
3. 删除字段、改字段含义、改枚举值、改默认值属于破坏性变更：`schemaVersion` +1，并提交 ADR 说明迁移方案。
4. 任何新枚举值必须同步更新三端、`docs/契约冻结.md` 与本轮裁决记录，并运行一致性检查。
5. CI 必须执行 `node scripts/check-contract-parity.mjs`；失败不得合并。
6. 禁止在 Rust/Python/React 内定义"临时同义枚举"或字符串别名绕过契约。
